# Operations Runbook and Support Model

Name an owner and backup owner for application, database, infrastructure, security, payment integration, customer communications, and business operations.

| Severity | Example | Target response |
|---|---|---|
| SEV-1 | Outage, data leak, duplicate/incorrect financial impact | Immediate escalation |
| SEV-2 | Critical workflow unavailable for many users | Urgent same-day response |
| SEV-3 | Workaround available | Planned support window |
| SEV-4 | Enhancement/question | Backlog triage |

Complete runbooks for deployment/rollback, database migration failure, backup restore, payment-webhook backlog, provider outage, credential rotation, user lockout/MFA reset, tenant suspension, suspicious access, data request, incident communication, and post-incident review. Before release, verify contacts, dashboards, alerts, backups, access review, dependencies, rollback owner, change ticket, and customer communication template.
